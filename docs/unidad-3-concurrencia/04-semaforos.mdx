**Idea central:** Un semáforo es una variable entera especial usada para sincronizar procesos. A diferencia de las variables normales, solo se puede acceder a ella mediante dos operaciones atómicas inseparables: `wait()` y `signal()`.

### Las operaciones `wait()` y `signal()`

Inventados por Edsger Dijkstra, los semáforos históricamente usaban las letras holandesas **P** (*Proberen* - probar/esperar) y **V** (*Verhogen* - incrementar).

*   **`wait(S)` o `P(S)`:** Decrementa el valor del semáforo. Si el resultado es menor que 0, el proceso se bloquea y se pone en una cola de espera[cite: 15].
*   **`signal(S)` o `V(S)`:** Incrementa el valor del semáforo. Si el resultado es menor o igual a 0, significa que había alguien esperando, así que despierta a un proceso de la cola[cite: 15].

> **¿Qué significa que el valor sea negativo?**
> Si un semáforo tiene el valor `-3`, significa que el recurso está ocupado y hay exactamente **3 hilos bloqueados en la cola** esperando su turno[cite: 15].

### Semáforo Binario vs Semáforo Contador

Existen dos tipos principales[cite: 15]:
1.  **Semáforo Binario (Mutex):** Su valor solo puede ser 0 o 1. Sirve para garantizar la exclusión mutua (proteger una sección crítica). Es como la llave de un baño público.
2.  **Semáforo Contador:** Su valor puede ser cualquier número. Sirve para controlar el acceso a un conjunto de recursos idénticos (ej. 5 impresoras).

### El Problema Clásico: Productor - Consumidor

Imagina una fábrica de pasteles (Productor) que los pone en un mostrador de 5 espacios (Buffer), y un cliente (Consumidor) que los compra.
* Si el mostrador está lleno, el productor debe detenerse.
* Si el mostrador está vacío, el consumidor debe detenerse.

Para resolverlo sin condiciones de carrera, usamos tres semáforos[cite: 15]:
1.  `mutex` (Binario, inicializado en 1): Protege el buffer para que no se modifique al mismo tiempo.
2.  `vacios` (Contador, inicializado en N): Cuenta cuántos espacios libres quedan[cite: 15].
3.  `llenos` (Contador, inicializado en 0): Cuenta cuántos elementos hay para consumir[cite: 15].

#### Ejemplo en Python con `threading.Semaphore`

```python
import threading
import time
import random

MAX_BUFFER = 5
buffer = []

# Declaración de semáforos
mutex = threading.Semaphore(1)
vacios = threading.Semaphore(MAX_BUFFER)
llenos = threading.Semaphore(0)

def productor():
    while True:
        item = "📦"
        vacios.acquire()     # Equivalente a wait(vacios)
        mutex.acquire()      # Bloquea el buffer
        
        buffer.append(item)  # SECCIÓN CRÍTICA
        print(f"Produce: {len(buffer)} items")
        
        mutex.release()      # Desbloquea el buffer
        llenos.release()     # Equivalente a signal(llenos)
        time.sleep(random.uniform(0.5, 1.5))

def consumidor():
    while True:
        llenos.acquire()     # wait(llenos) - Espera a que haya algo
        mutex.acquire()      # Bloquea el buffer
        
        buffer.pop(0)        # SECCIÓN CRÍTICA
        print(f"Consume: {len(buffer)} items")
        
        mutex.release()      # Desbloquea el buffer
        vacios.release()     # signal(vacios) - Avisa que hay un espacio libre nuevo
        time.sleep(random.uniform(1, 2))

# Iniciar hilos
threading.Thread(target=productor).start()
threading.Thread(target=consumidor).start()
```

#### 🧪 Experimento para la defensa (Pruébalo arriba)

Para entender a fondo este mecanismo, realiza estas dos pruebas interactivas:

1. **Comportamiento como Mutex (Valor inicial = 1):** Configura el valor en 1 y haz clic en P1. P1 entrará. Luego haz clic en P2. Verás que el valor cae a `-1`, indicando que P2 se bloquea. Esto demuestra la exclusión mutua perfecta[cite: 22].
2. **Control de Recursos Múltiples (Valor inicial = 3):** Reinicia con valor 3 y haz clic sucesivamente en P1, P2, P3 y P4. Los tres primeros entrarán (`wait()` los deja pasar restando 1 cada vez), pero al hacer clic en P4, el semáforo caerá a `-1` y P4 quedará bloqueado en la cola porque ya no hay recursos libres[cite: 22].
