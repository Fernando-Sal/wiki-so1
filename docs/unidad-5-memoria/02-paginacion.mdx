**Idea central:** Para solucionar la fragmentación externa de la asignación contigua, la paginación permite dividir un programa y guardarlo en pedazos dispersos por toda la RAM.

Para que esto funcione, se igualan los tamaños:

*   **Páginas lógicas:** el código del programa se corta en bloques exactos.
*   **Marcos físicos:** la memoria RAM se corta en bloques del mismo tamaño exacto.

### El proceso de traducción

Cuando la CPU quiere ejecutar una línea de código, no usa la dirección física directamente. Usa una dirección virtual que se divide automáticamente.

### La matemática detrás de la traducción

Cuando un programa intenta acceder a una dirección de memoria virtual, la Unidad de Gestión de Memoria (MMU) del procesador debe traducirla a una dirección física real en la RAM. Para lograrlo, divide la dirección virtual en dos partes:

1.  **Número de página** = `dirección ÷ tamaño de página` *(división entera)*.
2.  **Desplazamiento (offset)** = `dirección mod tamaño de página` *(el residuo de la división)*.

Con el número de página, el sistema consulta la **tabla de páginas** del proceso para saber en qué marco físico está guardada esa página. Finalmente calcula la dirección real:

*   **Dirección física** = `marco × tamaño de página + desplazamiento`

> **El fallo de página (page fault):** como la RAM es limitada, no todas las páginas del programa están cargadas a la vez. Si la tabla indica que una página no está en memoria (valor nulo o bit de validez en 0), ocurre un *fallo de página*. El SO debe pausar el programa, ir al disco, traer la página a un marco libre y actualizar la tabla.

### El problema: fragmentación interna

La paginación elimina por completo la fragmentación *externa*, pero crea la **fragmentación interna**. Como la memoria solo se entrega en bloques completos de tamaño fijo, la última página de un programa casi nunca se llena al 100 %.

#### Cálculo de ejemplo

Un proceso pesa **7 000 bytes** y el SO usa páginas de **1 024 bytes**:

1.  **Páginas requeridas:** 7000 / 1024 = 6,83. El SO no da medias páginas, así que asigna **7 páginas** completas.
2.  **Memoria total asignada:** 7 × 1024 = **7 168 bytes**.
3.  **Fragmentación interna:** 7168 − 7000 = **168 bytes desperdiciados** en el último marco.

### La solución de velocidad: la TLB

Consultar la tabla de páginas (que vive en la RAM) en *cada* instrucción es muy costoso: para leer una variable, la CPU haría **dos accesos a memoria**, uno para leer la tabla y traducir, y otro para leer el dato real. Cada acceso tardaría el doble.

Para evitarlo, los procesadores incluyen una **TLB (Translation Lookaside Buffer)**, una caché ultrarrápida dentro de la CPU que guarda las traducciones más recientes. Si la traducción está en la TLB (acierto de TLB), se evita el doble acceso a la RAM.

### Puntos clave

*   El tamaño de página siempre es una potencia de 2 (1024, 4096...) porque permite usar operaciones binarias de corrimiento (*bit shifting*) en lugar de divisiones, haciendo la traducción muy rápida.
*   En el widget, si borras el número de marco de la página activa, simulas cómo el procesador se topa con un espacio vacío y lanza un fallo de página.
